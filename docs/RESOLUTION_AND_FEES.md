## 1. Resolution source (5-minute BTC/ETH Up-or-Down markets)

**Source:** Polymarket Gamma API event object for a settled 5-minute BTC market
(`GET https://gamma-api.polymarket.com/events?slug=btc-updown-5m-1790673000`,
retrieved 2026-09-29), quoting the market `description` verbatim:

> This market will resolve to "Up" if the time-weighted average price (TWAP) of
> Bitcoin, generated by Chainlink, of the time range specified in the title is
> **greater than or equal to** the price at the beginning of that range.
> Otherwise, it will resolve to "Down".
> The resolution source for this market is information from Chainlink,
> specifically the BTC/USD TWAP data stream available at
> https://data.chain.link/streams/btc-usd-twap-60s-streams.
> Please note that this market is about the price according to the TWAP
> Chainlink data stream for the asset pair BTC/USD, **not according to any
> other sources or spot markets**.

Verified facts and their consequences:

| Fact | Consequence for this bot |
| --- | --- |
| Resolution source is the **Chainlink BTC/USD TWAP-60s** data stream (ETH markets: the analogous ETH/USD stream; UNVERIFIED — verified only for BTC, assumed symmetric for ETH) | The Binance BTCUSDT/ETHUSDT spot feed we consume is **not** the resolution source; it is a proxy. A basis between the two is real model risk (see §3). |
| Up iff **TWAP over the window ≥ price at window start** ("price to beat"); **ties resolve Up** | The strike/start price is the Chainlink TWAP value at the window's open, not a Binance print. Tie→Up slightly favors "Up" at exact-flat windows. |
| The API exposes the realized values per settled event: `eventMetadata.priceToBeat` (start TWAP) and `eventMetadata.finalPrice` (end TWAP) | Historical settlement ground truth is obtainable **without credentials** for basis measurement (§3). Example from the cited event: priceToBeat 83756.05446033228, finalPrice 83756.14974079143 → resolved Up. |
| `cryptoMarketConfig`: `{ asset: "btc", duration: "5m", twapEnabled: true, twapLookbackSeconds: 60 }` | The 5-minute markets use a 60 s TWAP lookback inside the window. |
| CLOB market params: `orderPriceMinTickSize: 0.001`, `orderMinSize: 5` (shares) | Tick and minimum order size for planning/limits. |
| Windows align to 5-minute UTC boundaries (`eventStartTime 2026-09-29T09:10:00Z`, `endDate ...09:15:00Z`) | Confirms the 300 000 ms cycle assumption in `MARKET_CYCLE_MS`. |

**UNVERIFIED:** whether Chainlink TWAP values are publicly retrievable as a
historical time series without a paid Chainlink subscription. We therefore
approximate the TWAP with the highest-frequency public series available
(Binance 1 m klines) and treat the difference as basis risk (§3). The
`priceToBeat`/`finalPrice` metadata above is the authoritative per-market
ground truth we *can* fetch.

## 2. Fee schedule (taker fees, crypto markets)

**Sources:**
- Official docs: https://docs.polymarket.com/trading/fees (retrieved 2026-09-29)
- Confirmed per-market via the Gamma API `feeSchedule` on the cited event:
  `{ exponent: 1, rate: 0.07, takerOnly: true, rebateRate: 0.2 }`, `feeType:
  "crypto_fees_v2"`, `feesEnabled: true` (retrieved 2026-09-29).

Verified formula (docs, verbatim structure):

```
fee = C × feeRate × p × (1 − p)
```

where `C` = number of shares traded and `p` = price per share. Per market
category (docs table): **Crypto taker fee rate = 0.07**, maker fee rate = 0
("Makers are never charged fees. Only takers pay fees."), maker rebate = 20% of
taker fees redistributed daily. Fees are calculated in USDC, symmetric around
0.50 (docs example table: 100 shares at $0.50 → $1.75 taker fee = 100 × 0.07 ×
0.25), rounded to 5 decimal places; the smallest charged fee is 0.00001 USDC.

Per-share taker fee used throughout this repo (Decimal, 8 dp):

```
feePerShare(p) = feeRate × p × (1 − p)        // feeRate default 0.07
```

Configuration (all in `packages/shared` config, defaults documented in
`docs/ENVIRONMENT.md`):

- `FEE_TAKER_RATE` (default `0.07`) — crypto taker fee rate; source URL comment
  in `packages/shared/src/config/schema.ts`.
- `FEE_TAKER_ONLY` (default `true`) — makers are never charged (docs).
- `FEE_REBATE_RATE` (default `0.2`) — informational for maker rebate accounting;
  the paper adapter applies rebates only where an explicit rebate is configured.

**UNVERIFIED:** whether the crypto category rate applies uniformly to all
BTC/ETH 5-minute series over time (the docs are point-in-time; the Gamma
`feeSchedule` per market is authoritative at runtime — the backtest reads it
per market when available and falls back to config).

## 3. Basis: Chainlink TWAP (resolution) vs Binance spot (our feed)

The strategy consumes the Binance BTCUSDT/ETHUSDT feed (read-only WebSocket).
Because resolution uses Chainlink TWAP-60s, every signal priced off Binance
carries basis risk. Measurement plan (implemented with the backtest recorder,
see `packages/backtest`):

1. For each settled 5-minute market in a window, fetch
   `eventMetadata.priceToBeat` / `finalPrice` from the Gamma API (real
   resolution values).
2. Fetch Binance 1 m klines for the same window (public REST, no credentials).
3. Report: sign-agreement rate (Binance-implied direction vs actual
   resolution), absolute basis at window open/close in USDC and in probability
   space, and how often the basis crosses zero between open and close.

Results are reported in `reports/backtest-24h.md` (T11) over the backtest
window; the basis is **not** corrected away — it is disclosed as a systematic
uncertainty, and the settlement in the backtest uses the *real* resolution
outcome (priceToBeat vs finalPrice), never a Binance-derived guess.

## 4. What would change live behavior (pre-registered, not implemented)

This section records, without implementing anything, the conditions under which
these facts would need re-verification before live trading:

- A change of `feeType` / `feeSchedule.rate` on live markets (read per market at
  runtime, never trusted from cache older than one cycle).
- A change of resolution source or tie rule (monitor the market description on
  each new market; any mismatch with §1 must halt new orders — UNVERIFIED
  fallbacks are config-only today).
